# Акции РФ: рабочий стол аналитика и инвесткомитет

## Когда использовать
- «Следи за акцией X», «добавь X в список», «перестань следить за X», «что у меня в списке».
- «Разбери X», «стоит ли покупать/держать X», «что думает комитет про X», «почему упала X».
- «Вышел отчёт X — что изменилось», «что нового по моим акциям», «сводка по списку».
- Вопросы про дивиденды, байбэки, допэмиссии, оценку, сравнение компаний одного сектора.
- **Портфель:** «мой портфель: SBER, LKOH, MGNT», «у меня 100 SBER по 280», «что с портфелем сегодня»,
  «разбери торги по моим акциям», «недельный обзор», «каждый день присылай брифинг» — процедуры E–G
  (семейный офис, `references/family-office.md`).

## Главная идея
1. **Память — в папке акции, а не в голове.** Каждая акция под наблюдением имеет папку в хранилище
   (`~/stocks-desk/<ТИКЕР>/`, переменная `STOCKS_DESK` меняет корень). Всё найденное — отчёты, новости,
   цифры, выводы, проверенные слухи — сохраняется туда. Перед любой работой по акции СНАЧАЛА прочитай
   её `README.md`, `thesis.md`, хвост `journal.md` и последний файл в `analyses/`. Новый разбор строится
   на старом: что изменилось с прошлого раза, подтвердились ли триггеры.
2. **Вывод выносит инвесткомитет**, а не один голос. Порядок заседания, роли и правила голосования —
   в `references/expert-panel.md`. Адвокат дьявола обязателен всегда.
3. **Только свежие данные с датой и источником.** Цены, ставки, отчёты, дивиденды — из первоисточника в
   момент работы, никогда из памяти модели.

## Инструменты (`scripts/`, Python 3.9+, только stdlib; для PDF — `pypdf`)
| Скрипт | Что делает |
|---|---|
| `desk.py add/list/status/show/analysed/log/remove/path` | Список наблюдения и папки акций: создать папку с профилем и шаблоном тезиса, показать, что изменилось с последнего разбора (цена, новые новости, близкие отсечки, устаревший разбор), записать итог комитета и события в хронологию |
| `moex_share.py <тикер> [--save] [--json]` | Карточка с MOEX: цена, капитализация, ликвидность, доходность 1м–3г против IMOEX, 52-нед. диапазон, волатильность, просадка, дивиденды по годам, LTM-дивдоходность, объявленные отсечки. `--save` дописывает `market/prices.csv`, `dividends.json`, `snapshots.jsonl` |
| `news.py [тикеры] [--days N] [--all] [--query ...] [--add-feed URL]` | Новости из Google News RSS и своих RSS в `news/news.jsonl` без дублей; помечает ⚑ существенные по заголовку (дивиденды, отчёты, сделки, суды, санкции…) |
| `gir_bo.py <ИНН> [--save ТИКЕР]` | РСБУ из ГИР БО ФНС по годам + маржи, долг, ROE, рост г/г → `financials/rsbu.json` |
| `report_extract.py <URL/PDF> [--save ТИКЕР --name 2026-h1-ifrs]` | Текст из PDF и ключевые строки (выручка, EBITDA, долг, FCF, дивиденды, EPS, казначейские акции, гайденс, аудитор); `--save` кладёт PDF и текст в `reports/` и пишет в `reports/index.md` |
| `portfolio.py set/add/update/trade/remove/import/list` | Портфель пользователя в `portfolio.json`: список тикеров, по желанию количество, средняя цена, сектор, целевая доля (`SBER:100@285`). Каждая бумага автоматически ставится на наблюдение и получает папку |
| `portfolio.py session [--save] [--alerts]` | Разбор последней торговой сессии по портфелю: цена, день против IMOEX, гэп, оборот к среднему за 20 дней, положение закрытия в диапазоне, 5д/1м, 52 нед., 200-дн. средняя, доля и вклад в результат, P&L, отсечки с последним днём покупки, состояние тезиса; сигналы ⚑; фон рынка (индексы и секторные индексы, юань, курсы ЦБ, Brent). `--save` → `_portfolio/daily/`, `history.csv`, цены в папки акций |
| `portfolio.py review [--save]` | Недельный обзор: доходность портфеля против IMOEX (неделя / месяц / 3 мес. / год / YTD), волатильность, бета, просадка, связанные пары, вклад бумаг, тезисы, отсечки |
| `valuation.py [--ticker X] ...` | Мультипликаторы (P/E, EV/EBITDA, P/B, ROE, дивдоходность, payout, FCF yield), DCF в трёх сценариях, таблица чувствительности, обратный DCF, модель Гордона |

Запуск: определи папку навыка (где лежит этот SKILL.md) и вызывай `python <папка_навыка>/scripts/desk.py ...`.
Типовые места: Hermes — `~/.hermes/skills/finance/ru-stocks/` или `~/.hermes/profiles/stocks/skills/finance/ru-stocks/`;
OpenClaw — `~/.openclaw/skills/ru-stocks/` или `<workspace>/skills/ru-stocks/`; Claude Code — `~/.claude/skills/ru-stocks/`.
В Windows, если `python` не найден, пробуй `python3` или `py`.

Справочники (читай по необходимости; в Hermes — `skill_view(ru-stocks, <путь>)`):
- `references/expert-panel.md` — **инвесткомитет**: роли, вопросы каждого эксперта, порядок заседания, голосование. Читать перед каждым разбором.
- `references/analysis-framework.md` — методология: бизнес, финансы, качество прибыли, оценка, дивиденды, корпоративное управление в РФ, отраслевые метрики, красные флаги, скоринг.
- `references/desk-structure.md` — что лежит в папке акции и как её вести.
- `references/data-sources.md` — где брать данные (биржа, раскрытие, ЦБ, ФНС, СМИ, форумы).
- `references/reading-reports.md` — как читать МСФО/РСБУ/презентации и что пересчитывать.
- `references/news-forums.md` — новости и форумы: сбор, проверка, статусы.
- `references/report-template.md` — шаблон протокола комитета, сводок, ежедневного брифинга и недельного обзора.
- `references/family-office.md` — **семейный офис**: команда, ежедневный брифинг по портфелю, недельный обзор, правила эскалации в комитет. Читать перед процедурами E–G.

## Процедуры

### 0. «Следи за X» — постановка на наблюдение
1. `desk.py add X --note "<зачем, если пользователь сказал>"`. Если тикер неоднозначен — покажи варианты и уточни (обычка/преф, например SBER/SBERP).
2. Сразу запусти первичный сбор (шаг 1 процедуры A) и **первичный глубокий разбор** (A целиком), если пользователь не сказал «просто добавь».
3. Скажи пользователю, где папка и что будет отслеживаться.

### A. Глубокий разбор (первичный или полный пересмотр)
1. **Сбор в папку** (параллельно, где можно):
   - `moex_share.py X --save` — рынок и дивиденды.
   - `news.py X --days 90 --all` — фон новостей за квартал; ⚑-новости открой и проверь.
   - Найди последнюю отчётность МСФО (сайт компании → «Инвесторам»; e-disclosure.ru по ИНН) и презентацию → `report_extract.py <URL> --save X --name <год-период-тип>`; прочитай ключевые разделы целиком (см. `reading-reports.md`). Предыдущий сопоставимый период — тоже.
   - `gir_bo.py <ИНН> --save X` — РСБУ (особенно если дивиденды считаются от РСБУ или это холдинг).
   - Ключевая ставка, прогноз ЦБ, доходность длинных ОФЗ (cbr.ru, КБД) — для ставки дисконтирования; отраслевые драйверы (цены сырья, курс, тарифы, регулирование).
   - Корпоративные события: дивполитика, решения СД, ГОСА, байбэк, допэмиссии, сделки с акционерами, санкции, суды (e-disclosure, kad.arbitr.ru).
   - Форумы и Telegram по `news-forums.md` → `forums/<дата>.md` со статусами проверки.
2. **Таблица фактов**: заполни/обнови `financials/ifrs.md` (ключевые показатели по периодам с источником) и профиль `README.md` (бизнес, акционеры, дивполитика, ключевые метрики, календарь).
3. **Оценка**: `valuation.py` — мультипликаторы против своей истории и сектора (сравнить с 3–5 аналогами, `moex_share.py` по каждому), DCF/дивмодель с явными допущениями, обратный DCF (что уже в цене).
4. **Заседание инвесткомитета** строго по `expert-panel.md`: независимые мнения → атака адвоката дьявола → ответы → голосование → решение председателя. Если среда умеет запускать субагентов (Claude Code — инструмент Task/Agent, Hermes — делегирование), запускай экспертов параллельно и **независимо** (каждому — его роль из `expert-panel.md` и путь к папке акции), затем передай все мнения адвокату дьявола и председателю. Иначе играй роли последовательно, не подглядывая в выводы следующих.
5. **Сохранение**: протокол целиком — `analyses/<YYYY-MM-DD>-committee.md` (шаблон `report-template.md`); обнови `thesis.md` (тезис, антитезис, диапазон стоимости, триггеры пересмотра, что проверить в следующем отчёте); `desk.py analysed X --verdict "<вердикт>" --score <0–100> --target <база ₽>`.
6. **Ответ пользователю**: TL;DR решения комитета, голоса, ключевые аргументы за/против, оценка, триггеры, ссылка на файл протокола.

### B. Обновление («что нового по X», «вышел отчёт», плановый мониторинг)
1. Прочитай `thesis.md` и последний протокол.
2. `desk.py status X`, `news.py X`, `moex_share.py X --save`; если вышел отчёт — архивируй его (`report_extract.py --save`) и обнови `financials/ifrs.md`.
3. Сверь факты с **триггерами пересмотра** и «что проверить в следующем отчёте» из тезиса.
4. Если тезис не задет — короткая сводка (шаблон «Сводка» в `report-template.md`) + запись в `journal.md` через `desk.py log`.
   Если задет триггер, цена ушла > 15% от разбора, вышла годовая/полугодовая отчётность, сменилась дивполитика или прошло > 90 дней — **созови комитет** (процедура A, шаги 3–6), сфокусировав его на изменениях.

### C. Сводка по всему списку («что по моим акциям»)
1. `desk.py status` и `news.py` (без тикеров — по всем).
2. По каждой акции с ⚑ — процедура B. Остальные — одной строкой.
3. Итог: таблица «тикер — цена/изменение — вердикт комитета — что случилось — нужно ли действие».

### D. Сравнение / выбор в секторе
Собери карточки и мультипликаторы по всем кандидатам, приведи к сопоставимому виду (LTM, одна валюта, одинаковые корректировки), проведи сокращённый комитет по каждому и общий итог: кто лучший по соотношению качество/цена и почему.

### E. Портфель: состав («мой портфель…», «купил…», «продал…»)
1. Пользователь даёт список акций: `portfolio.py set SBER LKOH MGNT` (заменяет состав) или `portfolio.py add X`.
   Если он назвал количество и среднюю цену — `TICKER:QTY@AVG` (например `SBER:100@285,4`), иначе портфель
   считается равновзвешенным. Не требуй количество, если пользователь его не дал; можно один раз предложить.
   Выгрузку брокера в CSV — `portfolio.py import file.csv`. Если выгрузка в XLSX, PDF или на скриншоте,
   прочитай её сам и собери строку для `set`.
2. Сделки со слов пользователя («купил ещё 50 Сбера по 300», «продал половину Магнита») — `portfolio.py trade X buy|sell КОЛ-ВО [ЦЕНА]`: скрипт сам пересчитает количество и среднюю цену и запишет в хронологию. Неоднозначные тикеры (обычка/преф) уточни. Сектор и целевую долю можно задать: `portfolio.py update X --sector … --target 10`.
3. Бумаги без разбора комитета ставятся в очередь первичного разбора (процедура A). Если бумаг много,
   разбирай по 1–2 за раз, начиная с самой крупной доли, и скажи пользователю, в каком порядке пойдёшь.
4. Покажи `portfolio.py list` и скажи, что дальше будет приходить ежедневный брифинг (процедура F) — если
   пользователь хочет, настрой расписание (раздел «Мониторинг по расписанию»).

### F. Ежедневный брифинг семейного офиса («что с портфелем», плановый запуск после закрытия)
Строго по `references/family-office.md`, раздел «Ежедневный брифинг»:
`portfolio.py session --save` → `news.py <тикеры портфеля> --days 3` и проверка ⚑ по первоисточнику →
объяснение каждого сигнала (почему двигалась бумага) → сверка с `thesis.md` → риск → календарь на 14 дней →
вопрос адвоката дьявола → эскалация в комитет по правилам → брифинг в `_portfolio/briefs/<дата>.md`
(шаблон 4 в `report-template.md`) → короткое сообщение владельцу.

### G. Недельный обзор портфеля
По `family-office.md`, раздел «Недельный обзор»: `portfolio.py review --save`, новости за неделю, атрибуция,
здоровье тезисов и очередь комитетов, риск и баланс, календарь на 2 недели → `_portfolio/reviews/<дата>.md`
(шаблон 5).

## Правила (обязательные)
- **Не выдумывай цифры.** Каждая цифра — с источником (скрипт / URL / страница отчёта) и датой. Различай МСФО группы и РСБУ юрлица, обычку и преф, LTM и прогноз.
- **Пересчитывай сам**: FCF, чистый долг (с арендой и без), payout, EPS на акции в обращении (без казначейских). «Скорректированные» метрики компании — только со сверкой.
- **Новости и форумы — гипотезы до проверки** первоисточником; статусы ✅/❌/⚠️/💬 по `news-forums.md`.
- **Адвокат дьявола обязателен** в каждом разборе, и его главный аргумент обязан попасть в итог, даже если комитет его отверг.
- **Пиши в папку.** Результат, не сохранённый в папку акции, считается потерянным: протокол, тезис, хронология, архив отчётов.
- Это аналитика, а не индивидуальная инвестиционная рекомендация: сценарии, риски и взвешенный вывод; решение — за пользователем. Сделки не исполняешь, доступы к брокерскому счёту не просишь.
- Ответ на русском, сначала вывод (TL;DR), потом аргументы. Суммы — в ₽ с разрядами, доли — в %, ставки — в % годовых.
- При отказе MOEX/ГИР БО — повтори, затем используй веб-источники (smart-lab, dohod, investing, сайт компании) и отметь это.

## Мониторинг по расписанию (cron Hermes / OpenClaw, задачи по расписанию Claude)
Расписание держит среда агента, а не скрипты. Задание должно быть самодостаточным: в запуске по расписанию
агент не помнит разговор, поэтому в тексте задания назови навык и процедуру.
- **Ежедневный брифинг:** будни, 19:15 МСК — «Используй навык ru-stocks, процедура F: ежедневный брифинг семейного офиса по моему портфелю (portfolio.json), сохрани брифинг и пришли короткое сообщение».
- **Недельный обзор:** суббота, 10:00 МСК — «…процедура G: недельный обзор портфеля».
- **Дневная проверка (по желанию):** будни, 13:00 МСК — «…`portfolio.py session --alerts`; пиши, только если есть сигнал ⚑ с движением больше 5% или новость ⚑ по бумаге портфеля».
- Список наблюдения без портфеля: «каждый будний день в 19:00 сделай сводку по списку (процедура C); присылай, только если есть ⚑».

Hermes: `hermes cron create "15 19 * * 1-5" "<текст задания>" --skill ru-stocks --name "Брифинг портфеля" --timezone Europe/Moscow`
(или просто попросите в чате «каждый будний день в 19:15 присылай брифинг по портфелю»). Задания выполняет
шлюз: `hermes gateway` должен быть запущен (`hermes gateway install` ставит его службой).
OpenClaw: `openclaw cron add "15 19 * * 1-5" "<текст задания>" --name "Брифинг портфеля" --tz Europe/Moscow` (нужен запущенный Gateway).
Claude: задачи по расписанию (Scheduled tasks) в приложении Claude или `/schedule` в Claude Code с тем же текстом.
